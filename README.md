# Feynman Quest

> Learn the language of the universe, one interaction at a time.

Feynman Quest is a mobile puzzle game about particle physics. It starts out approachable and ends up as a Feynman diagram lab. Players **decode** diagrams, **build** them from draggable pieces and **debug** mistakes, while a deterministic validator explains why each solution works or fails.

Available in **English, Spanish and Catalan**.

**Play:** https://manuel-martos.github.io/feynman/ (PWA, installable and available offline)

Product proposal: [docs/feynman_quest_product_proposal.md](docs/feynman_quest_product_proposal.md)

## What the MVP includes

- **34 levels** across 7 chapters, mixing the three mechanics: Decode, Build and Debug.
- **QED with electrons, positrons and photons**:
  - Chapters 1–5, tree level: Møller, Bhabha, annihilation, Compton and pair production.
  - Chapter 6, higher order: bremsstrahlung, positronium decay into three photons, counting diagrams and identical bosons.
  - Chapter 7, loops: vacuum polarization, Schwinger's g−2, light-by-light scattering, Furry's theorem and the Møller box.
- **Watch it in time**: any diagram plays back as a story. Lines are drawn from left to right and particles travel along the diagram carrying the sign of their charge. Each vertex is explained with its charge balance. You can play it or step through it, on the result screen, in the Collection and in some challenges.
- **Constrained editor**: drag between points and the line snaps to the nearest one. You can also connect with two taps or with the keyboard.
- **Three-layer validator**: structural, theoretical (QED vertex, charge flow) and physical (kinematics), plus each level's own goals (s/t/u channel, a different contribution).
- **Three explanation layers**: intuitive, scientific and mathematical. The mathematical one unlocks when chapter 1 is complete.
- **Progression**: stars (based on mistakes and hints, never on time), XP, ranks, chapter unlocks and local saves.
- **Collection** of 34 concepts and diagrams.
- **Mastery mode**: review with diagrams generated by the engine, always different and always correct.
- **Two-step hints**: the first points you in the right direction, the second shows the rule.
- **Synthesized sound, vibration, accessibility** (ARIA, keyboard, reduced motion) and an **offline PWA**.
- **Local user-testing metrics**, exportable as JSON from Settings. They are meant to validate the hypotheses in section 8 of the proposal.

## Architecture

```
src/
  engine/     Diagram Engine — pure TS, no UI dependencies
              typed graph · validator · topology (channels, equivalence, loops) ·
              tree enumerators · timeline (reading a diagram in time)
  game/       Game Engine — level types, scoring, progress (zustand + localStorage)
  content/    Content — Spanish source (es/), English and Catalan translations (locales/),
              validator messages, narration and Mastery-mode text per language
  i18n/       Interface text per language
  ui/         React — DiagramView (SVG), DiagramEditor, StepPlayer, screens
```

- Diagrams are **typed graphs**: nodes (external or vertices) and edges (fermion with an arrow, or photon). Geometry is presentation only.
- Topological equivalence uses the leaf partitions (*splits*) induced by internal lines, so two different drawings of the same diagram are recognised as the same.
- The **enumerators** generate every tree-level diagram, both for 2→2 and for any number of external particles. Tests use them to check the scientific claims in the content: for example, that Møller has t and u channels, that e⁻e⁻→e⁻e⁻γ has 8 diagrams, that e⁻e⁺→γγγ has 6 and that γγ→γγ has none at tree level.
- **Loops** are allowed per level (`loops`). The validator also applies **Furry's theorem**: an electron loop with an odd number of photons cancels out.

### Languages

- **Spanish is the source.** Levels and concepts are written in `src/content/es/`. English and Catalan are flat `path → text` overlays in `src/content/locales/{en,ca}/`, merged with `localize()`. A test checks that each translation covers exactly the Spanish strings.
- Sentences built from data (validator messages, "watch it in time" narration, Mastery-mode questions) have their own module per language, because the grammar differs: `src/content/{es,en,ca}/`.
- Interface text lives in `src/i18n/{es,en,ca}.ts`, typed against the Spanish dictionary so a missing key fails the build.
- Both apps follow the device or browser language and fall back to English. Settings has a picker, with "Automatic" as the default.

**Technical decision:** the proposal suggested Kotlin + Compose. For the MVP we chose a PWA (React + TypeScript + Vite) to validate as early as possible, on any device. The engine is pure TypeScript and separate from the UI, and a native port already exists (see [Native Android app](#native-android-app)).

## Native Android app

`android/` holds the fully native version, with the same design and content as the PWA:

```
shared/                       single source of truth exported from TypeScript (npm run export:shared)
  content/{es,ca,en}.json     levels, concepts, scoring, Mastery-mode text and art, per language
  engine-cases.json           golden cases from the TS engine (validator, topology, timeline,
                              narration and messages in every language, enumerators)
android/
  core/   pure Kotlin/JVM — port of the Diagram Engine and Game Engine, checked against the golden cases
  app/    Jetpack Compose — Material 3 Expressive, Navigation 3, Hilt, ViewModels + StateFlow, DataStore
```

- **Proven parity**: `:core:test` runs the Kotlin engine over hundreds of diagrams (all those in the content, enumerations, random mutations) and requires the same result as the TypeScript engine, including messages and narration in all three languages.
- **Single content source**: the app bundles `shared/content/*.json` as assets; CI fails if `shared/` is out of sync with `src/`.
- **Languages**: interface text is in `res/values` (English), `res/values-es` and `res/values-ca`. Android 13+ shows the language in the system's per-app language settings; the in-app picker works on every version.
- Diagrams drawn on a `Canvas` (glow, flow, timed playback with charges), touch editor, sound synthesized with `AudioTrack`, haptics, and reduced motion from the app or system setting.

```bash
npm run export:shared                  # after changing content or the engine in src/
cd android
./gradlew :core:test :app:testDebugUnitTest   # parity, logic and UI (Robolectric + Roborazzi)
./gradlew :app:installDebug            # install on the connected device
```

CI builds the debug APK and publishes it as an artifact (`feynman-quest-debug-apk`).

## Development

```bash
npm install
npm run dev        # development server
npm test           # engine, scoring, content and translation tests (Vitest)
npm run build      # production build + service worker
npm run e2e        # smoke and language tests in a mobile viewport (Playwright)
```

Every push to `main` goes through typecheck, unit tests and E2E, and is deployed to GitHub Pages.

## Scientific rigour

Every Build level has a reference solution that is validated in the tests, and every Debug diagram must fail with the expected error. Even so, as the proposal recommends, someone trained in particle physics should review the content before user testing.
